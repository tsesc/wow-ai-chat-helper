[S, quoting Blizzard] https://gamewave.fr/world-of-warcraft-forever/wow-forever-les-restrictions-d-addons-de-midnight-seront-aussi-appliquees/ ; also https://www.gfinityesports.com/article/world-of-warcraft-forever-ui-addons-setup-guide , https://kami-labs.fr/en/wow-classic/wow-forever-addons-restreints-comme-sur-midnight/

## Q2. Channels OUT of the game
1. Pixels/screen capture: works (wow-ai: coloured 4px cells, 3-bit/cell, ~3.2KB/frame, capture 4x/s, needs windowed/borderless). [P] https://github.com/chelinho139/wow-ai (docs/ARCHITECTURE.md). Also wow-forever-codex: B/W strip, 1,280 bytes max prompt, ~250 ms update cadence. [P] https://github.com/0xinuarashi/wow-forever-codex
2. /chatlog -> Logs\WoWChatLog.txt. LoggingChat([bool]) exists, addon-callable, in Forever. [P] https://warcraft.wiki.gg/wiki/API_LoggingChat . Flush: wowprogramming says "file is not actually updated until the player logs out" and "(but not necessarily all text displayed in chat windows)" [OLD] https://wowprogramming.com/docs/api/LoggingChat.html ; WoWInterface mod 2012-05-02: fixed small buffer (~2-4 KB), "intentional, as Blizzard does not want anything close to real-time communication in either direction between WoW and outside applications" [OLD] https://www.wowinterface.com/forums/showthread.php?t=43380 . NO modern (Forever/12.x) measurement found -> flush latency on Forever: [NV]; treat as unreliable/minutes. Per-channel coverage (whisper/party/guild/channel) and whether addon AddMessage output is logged: [NV] (docs say only "text received via the chat system").
3. /combatlog -> WoWCombatLog.txt. LoggingCombat rate-limited 5 calls/10s shared. No documented way for an addon to write arbitrary text into it [P, absence] https://warcraft.wiki.gg/wiki/API_LoggingCombat . Since 10.2 (2023-11) combat log is held in memory and written only at combat end [S x3, Blizzard EULA 1-C cited by one] https://wowcarry.com/blog/wow/patch-102-introduces-updates-to-combat-logs-measures-against-out-of-game-overlays , https://www.wowhead.com/news/combat-log-changes-with-patch-10-2-measures-to-prevent-out-of-game-overlays-335813 (headline only retrieved), https://mein-mmo.de/en/page/1120/?term=leya . Dead end for this use case. Midnight 12.0 also removed COMBAT_LOG_EVENT(_UNFILTERED) for addons [P] https://warcraft.wiki.gg/wiki/Patch_12.0.0/API_changes
4. SavedVariables: written only on logout/disconnect/quit/reload [P] https://warcraft.wiki.gg/wiki/Saved_variables . ReloadUI/C_UI.Reload needs hardware event (key/mouse) [P] https://warcraft.wiki.gg/wiki/API_ReloadUI . So not usable as timer-driven channel; latency = until user presses a key to reload (and reload interrupts play).
5. Screenshot(): saves jpg/png/tga to Screenshots folder, no documented restriction [P] https://warcraft.wiki.gg/wiki/API_Screenshot . Possible but heavy; no advantage over live pixel capture. Clipboard: no addon API found [NV]; user would have to copy from an EditBox manually.
6. Memory reading (BabelChat companion): reads addon buffer via pointer; ~0.5-2s translation latency; its own page admits memory reading "is not something Blizzard's EULA permits". [P] https://www.curseforge.com/wow/addons/babelchat

## Q3. Channels INTO the game
- Load-on-demand addon file trick: C_AddOns.LoadAddOn reads files at load time; each addon loads once per session; /reload unloads. wow-ai writes same payload to 200 pre-made slots, loads next on timer (5,10,16,24,34,46,60... s) or immediately on signal; ~1 slot per reply with signal, ~4 without; 200 slots/session. [P] https://github.com/chelinho139/wow-ai/blob/main/docs/ARCHITECTURE.md ; https://warcraft.wiki.gg/wiki/API_C_AddOns.LoadAddOn
- Empirical rule (measured on live Forever client by two projects): files must exist at client launch; a not-yet-loaded file is read fresh on first use; loaded files stay cached for the process (even across /reload) except addon Lua code. [P] https://github.com/0xinuarashi/wow-forever-codex (README, docs/font-recycling.md: full-restart reuse verified 2026-09-21) + wow-ai ARCHITECTURE. Two independent projects agree -> cross-checked.
- Font-metric channel (wow-forever-codex): bank of 65,535 pre-made .ttf files, bridge atomically replaces an unused one with a font whose glyph advance widths encode bytes (476 B payload/512 B packet); addon reads via SetFont/GetStringWidth; fresh slot request ~every 5 s (first window ~6 s). Explicitly "an empirical result ... not a guaranteed API". [P] README above.
- Sound-existence trick: PlaySoundFile returns willPlay; wiki says "file must exist prior to logging in or reloading" [P] https://warcraft.wiki.gg/wiki/API_PlaySoundFile ; wow-ai uses empty vs valid .wav as 1-bit flags (self-test at login; falls back to schedule if client reports empty as playable).
- SavedVariables files edited externally: only re-read on login/reload (TSM AppHelper / WeakAuras Companion pattern, see Q4).
- Keybinds/macros files: not researched in depth [NV]. wow-ai macro text is capped 255 B.
- Has Blizzard closed any recently? No evidence found of closure of LoD/file-first-use tricks (searched). Blizzard's pattern is breaking APIs (combat log 10.2, Midnight secret values) rather than bans (player-opinion only, https://us.forums.blizzard.com/en/wow/t/addon-development-automated-functions/1496311). Risk of future closure: [NV] but non-zero; the codex README itself calls it unguaranteed.

## Q5. ToS / policy
- Terms of Use/EULA forbid "cheats, automation software (bots), hacks, mods, or any other unauthorized third-party software designed to modify the WoW experience" [S] vlex/gamespot WoWGlider coverage: https://www.gamespot.com/articles/blizzard-wins-6m-in-wowglider-suit/1100-6198401/ . Primary EULA text not retrieved: [NV].
- Official UI Add-On Development Policy (2009): no obfuscation, no excessive chat use/"unnecessary loading from the hard disk", all addons must follow ToU/EULA; contact wowui@blizzard.com. [P] https://us.forums.blizzard.com/en/wow/t/ui-add-on-development-policy/24534
- Blizzard 10.2: acted against out-of-game overlays that give real-time combat instructions (EULA 1-C cited) by buffering combat log -> intent is combat advantage, not chat help. [S]
- Pixel reading: community claims pixel-rotation bots banned [S] (https://us.forums.blizzard.com/en/wow/t/bots-are-back/282442 not fetched). Ban risk stems from INPUT automation; no Blizzard statement found about read-only pixel capture of non-combat data: [NV]. wow-ai/codex projects state they inject nothing and read no memory but give no ToS guarantee.
- Chatlog tailing: no Blizzard statement found; WOWScribe-type chat logging addons exist for years. [NV]
- Writing addon files while game runs: TSM/WeakAuras companions do it routinely (widely tolerated); LoD slot pool is the same mechanism but used as live IPC: no Blizzard statement [NV].
- Memory reading (BabelChat): author admits EULA-prohibited; Warden detects banned software [S]. Highest risk.
- Chat sending must stay human-driven: addon-initiated SendChatMessage blocked in lockdown; do not auto-send AI replies (also automation-policy risk). Keep design as "show reply template, user presses Enter / copies".
- Other caveat: Chinese glyph rendering on a US-locale client with default fonts: [NV], test early (ship a CJK .ttf with the addon if needed).

## Ranked recommendation (chat in -> AI -> text back in game, few-second target)
1. Pixel strip OUT (CHAT_MSG_* events -> compact UTF-8 record, high-contrast 8-colour cells, windowed/borderless) + LoD slot pool IN with empty/valid .wav "ready" flag (wow-ai design, trimmed to chat-translation: short messages, only latest result). Pros: proven on Forever builds; ~1-6 s; fully in-game display, no /reload; read-only screen capture, no memory. Cons: needs windowed/borderless; 200-slot budget per session (reload resets); relies on undocumented first-use file rule that Blizzard could break; screen-capture ToS grey area; strip must be on screen (can be tiny/corner).
2. Same pixel-OUT but results shown in an always-on-top overlay window drawn by the helper over the game (no file-IPC into game). Pros: lowest latency (~0.5-2 s), no slot limit, no dependence on file-load quirk, Chinese text rendering trivially fine, nothing to break on Blizzard side except pixels. Cons: not literally "inside" the game UI (overlay needs borderless; breaks in exclusive fullscreen); two moving parts; same pixel-reading grey area. Easy to combine with #1 as fallback.
3. Fallback/low-tech: addon keeps history in SavedVariables; helper reads on /reload; replies via companion addon data file (TSM/WeakAuras pattern) loaded at /reload. Pros: widely used, lowest ToS risk, no pixels. Cons: latency = next /reload (hardware key); not interactive; only for end-of-session review/learning vocabulary.
Not recommended: BabelChat-style memory reading (explicit EULA violation); WoWChatLog.txt tailing (buffered/unreliable, no modern evidence, no addon-output); combat-log tricks (written only at combat end).
